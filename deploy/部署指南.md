# 部署指南 · 会议扫码签到系统

本指南面向**没有编程基础的老师**，一步步把系统部署到公网，部署完任何人用手机扫码都能签到。

全程约 15 分钟。需要准备：一个 GitHub 账号、一个 Railway 账号。

---

## 第 0 步：先看懂这套东西怎么跑

```
      你的电脑（打开大屏，投影到会场）
              │  浏览器打开后台，登录后点「打开签到大屏」
              ▼
    ┌───────────────────────────┐
    │   Railway 云端服务器      │  ← 网站跑在这里（公网）
    │   （网站 + 数据库）        │
    └───────────────────────────┘
              ▲
              │  参会老师手机扫大屏上的二维码 → 填姓名/手机号/校区/现场码
              │
      参会老师的手机（4G 流量）
```

要点：
- 大屏二维码里是**云端网址**，所以在校外也能扫；
- 二维码每 20 秒自动换一张，现场码也每 20 秒变一次，防止有人截图转发；
- 所有签到记录实时存在云端数据库，管理员随时看、随时导出。

---

## 第 1 步：把代码放到 GitHub

1. 打开 <https://github.com> 注册/登录账号。
2. 右上角点 `+` → **New repository**。
3. 仓库名填 `meeting-checkin`，勾选 **Add a README file**，其余默认，点 **Create repository**。
4. 在项目文件夹 `D:\MiniMax工作站\签到系统` 里按住 `Shift` 右键 → **在此处打开 PowerShell**，依次执行：

```powershell
git init
git add -A
git commit -m "init: 会议扫码签到系统"
git branch -M main
git remote add origin https://github.com/你的用户名/meeting-checkin.git
git push -u origin main
```

> 提示：第一次 push 会要求登录 GitHub，用**浏览器授权**即可。
> 若提示 `git` 不是命令，去 <https://git-scm.com/download/win> 下载安装后重试。

---

## 第 2 步：在 Railway 上创建项目

1. 打开 <https://railway.app>，用 **GitHub 账号登录**（右上角 Login → GitHub）。
2. 登录后首页点 **New Project → Deploy from GitHub repo**。
3. 找到你刚建的 `meeting-checkin` 仓库，点 **Deploy**。
   （这一步会先自动构建，可能因为还没有数据库变量而失败，属正常，继续往下走。）
4. 在项目页面点 **+ New** → **Database → PostgreSQL**，添加一个数据库。
   Railway 会自动把 `DATABASE_URL` 注入到你的服务里，不用自己填。

---

## 第 3 步：设置环境变量（关键）

在项目页面点你的 **服务卡片**（不是 Postgres 卡片）→ 顶部 **Variables** 标签 → 点 **+ New Variable**，逐条添加：

| 变量名 | 填写内容 | 说明 |
|---|---|---|
| `SECRET_KEY` | 点 **Generate** 自动生成 | 用于签到码加密，不要泄露 |
| `BASE_URL` | 先填 `https://你的域名`（下一步才知道） | 决定二维码扫出来跳到哪个网址 |
| `ADMIN_PASSWORD` | 自己设一个密码（至少 6 位） | 初始管理员 `admin` 的密码 |

> `BASE_URL` 怎么填？先跳到第 4 步拿到域名，回来改成
> `https://你的域名`（**不要带结尾斜杠**），保存后 Railway 会自动重新部署。

---

## 第 4 步：拿到网址并填回 BASE_URL

1. 在服务卡片点 **Settings** → 找到 **Networking** 区域 → 点 **Generate Domain**。
2. 会得到形如 `meeting-checkin-production.up.railway.app` 的地址。
3. 浏览器打开它，看到登录页即部署成功。
4. 回到 **Variables**，把 `BASE_URL` 改成 `https://meeting-checkin-production.up.railway.app`，保存。

---

## 第 5 步：第一次登录

1. 打开你的网址，登录：
   - 用户名：`admin`
   - 密码：第 3 步设置的 `ADMIN_PASSWORD`
2. 登录后建议立刻：
   - 「账号管理」→ 把 `admin` 密码改成你习惯的密码；
   - 「账号管理」→ 给其他教务老师各建一个账号（他们只能管自己的活动）。
3. 「新建活动」→ 填名称、时间、地点、勾选校区等 → 保存。
4. 进入活动后台 → 点右上角 **「打开签到大屏」** → 会开一个新页面，投影出去即可。

---

## 第 6 步：用起来

### 会前
1. 后台「导入名册」→ 先「下载模板」→ 在 Excel 里填（**姓名、校区必填**）→ 上传。
2. 检查「应到人数」是否正确。

### 会中
1. 大屏页面右上角可切换 **签到模式 / 签离模式**。
2. 参会者扫二维码 → 填姓名、手机号、选校区、**输入大屏上显示的 4 位现场码** → 提交。
3. 大屏右侧「最新动态」实时滚动，已签到/已签离数字每 2 秒刷新。

### 会后
1. 后台 →「导出 Excel」→ 得到三张表：**签到明细 / 应到实到统计 / 缺席名单**。
2. 忘记扫码的老师，用「手动补录」补上（会标记为「补录」）。

## 常见问题对照表

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 打开网址显示 502 / Application Error | 构建失败或服务没起来 | Railway → 服务 → **Deployments** → 看红色日志；多半是 `DATABASE_URL` 没生效，确认 Postgres 插件在同一个项目里 |
| 扫码后跳转到空白页 | `BASE_URL` 填错 | 改成 `https://你的域名`（不带斜杠），保存后自动重新部署 |
| 大屏二维码一直不变 | 页面没刷新 | 按 `Ctrl+F5` 强制刷新；仍不行则检查 `CYCLE_SECONDS` 是否被改过 |
| 手机提交提示「签到码已刷新」 | 手慢，超过了 40 秒窗口 | 重新扫一次二维码，看最新现场码再填 |
| 手机提交提示「现场码不正确」 | 填的是上一轮的码 | 以大屏当前显示的数字为准 |
| 签到打不开 / 显示未开放 | 时间不在活动时段 | 后台「编辑」检查开始结束时间；注意服务器时区为北京时间 |
| 数据没了 | 用了免费实例且数据库未挂载 | 确认 Postgres 插件存在；免费版建议每月登一次避免休眠 |
| 多人同时签到很慢 | 免费实例性能有限 | Railway 升级付费实例（约 ¥20/月） |

## 费用说明

- Railway 免费额度：每月 $5 使用量，小规模使用（每月十几次会议、几十人签到）基本够用。
- Postgres 免费额度 0.5GB，签到记录体积很小，一年的数据也就几 MB。
- 正式长期使用建议用信用卡升级 Hobby 计划（约 $5/月），避免休眠导致二维码打不开。

---

## 安全提醒

- `SECRET_KEY` 决定签到码能否被伪造，**不要提交到 GitHub**（已在 `.gitignore` 中管理环境变量文件）。
- 参会老师手机号属于个人信息，导出表仅在校内使用，不要外传。
- 活动结束后建议把活动「归档」，避免误操作。
