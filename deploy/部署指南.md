# 部署指南 · 会议扫码签到系统

本指南面向**没有编程基础的老师**，一步步把系统部署到公网，部署完任何人用手机扫码都能签到。

全程约 15 分钟。需要准备：一个 GitHub 账号、一个 Railway 账号。

## 第 0 步：先看懂这套东西怎么跑

```
      你的电脑（打开大屏，投影到会场）
              │  浏览器打开后台，登录后点「打开签到大屏」
              ▼
    ┌───────────────────────────┐
    │   Railway 云端服务器      │  ← 网站跑在这里（公网）
    │   （网站 + 数据库）        │
    └───────────────────────────┘
              ▲
              │  参会老师手机扫大屏上的二维码 → 填姓名/手机号/校区/现场码
              │
      参会老师的手机（4G 流量）
```

要点：
- 大屏二维码里是**云端网址**，所以在校外也能扫；
- 二维码每 20 秒自动换一张，现场码也每 20 秒变一次，防止有人截图转发；
- 所有签到记录实时存在云端数据库，管理员随时看、随时导出。

## 第 1 步：把代码放到 GitHub

1. 打开 <https://github.com> 注册/登录账号。
2. 右上角点 `+` → **New repository**。
3. 仓库名填 `meeting-checkin`，勾选 **Add a README file**，其余默认，点 **Create repository**。
4. 在项目文件夹 `D:\MiniMax工作站\签到系统` 里按住 `Shift` 右键 → **在此处打开 PowerShell**，依次执行：

```powershell
git init
git add -A
git commit -m "init: 会议扫码签到系统"
git branch -M main
git remote add origin https://github.com/你的用户名/meeting-checkin.git
git push -u origin main
```

> 提示：第一次 push 会要求登录 GitHub，用**浏览器授权**即可。
> 若提示 `git` 不是命令，去 <https://git-scm.com/download/win> 下载安装后重试。

---

## 第 2 步：在 Railway 上创建项目

1. 打开 <https://railway.app>，用 **GitHub 账号登录**（右上角 Login → GitHub）。
2. 登录后首页点 **New Project → Deploy from GitHub repo**。
3. 找到你刚建的 `meeting-checkin` 仓库，点 **Deploy**。
   （这一步会先自动构建，可能因为还没有数据库变量而失败，属正常，继续往下走。）
4. 在项目页面点 **+ New** → **Database → PostgreSQL**，添加一个数据库。
5. **回到你的应用服务卡片 → Variables → + New Variable**，手工加一条：

   | 变量名 | 填写内容 |
   |---|---|
   | `DATABASE_URL` | `${{Postgres.DATABASE_URL}}` |

   > 这一步不能省。Railway 的数据库插件**不会**自动把 `DATABASE_URL` 注入到应用服务，
   > 不手工加这条引用变量，应用启动时连不上数据库会直接崩溃。

---

## 第 3 步：设置环境变量（关键）

在项目页面点你的 **服务卡片**（不是 Postgres 卡片）→ 顶部 **Variables** 标签 → 点 **+ New Variable**，逐条添加：

| 变量名 | 填写内容 | 说明 |
|---|---|---|
| `SECRET_KEY` | 点 **Generate** 自动生成 | 用于签到码加密，不要泄露 |
| `BASE_URL` | 先填 `https://你的域名`（下一步才知道） | 决定二维码扫出来跳到哪个网址 |
| `ADMIN_PASSWORD` | 自己设一个密码（至少 6 位） | 初始管理员 `admin` 的密码 |

> `BASE_URL` 怎么填？先跳到第 4 步拿到域名，回来改成
> `https://你的域名`（**不要带结尾斜杠**），保存后 Railway 会自动重新部署。

---

## 第 4 步：拿到网址并填回 BASE_URL

1. 在服务卡片点 **Settings** → 找到 **Networking** 区域 → 点 **Generate Domain**。
2. 会得到形如 `meeting-checkin-production.up.railway.app` 的地址。
3. **再把同区域的目标端口（Target Port）改成 `8000`**，保存。
   > 本项目的 gunicorn 固定监听 8000（Railway 新版运行时不再注入 `PORT` 环境变量），
   > 而域名默认指向 8080。不改这一项，网址会一直报 **502 Application failed to respond**。
4. 浏览器打开它，看到登录页即部署成功。
5. 回到 **Variables**，把 `BASE_URL` 改成 `https://meeting-checkin-production.up.railway.app`，保存。

---

## 第 5 步：第一次登录

1. 打开你的网址，登录：
   - 用户名：`admin`
   - 密码：第 3 步设置的 `ADMIN_PASSWORD`
2. 登录后建议立刻：
   - 「账号管理」→ 把 `admin` 密码改成你习惯的密码；
   - 「账号管理」→ 给其他教务老师各建一个账号（他们只能管自己的活动）。
3. 「新建活动」→ 填名称、时间、地点、勾选校区等 → 保存。
4. 进入活动后台 → 点右上角 **「打开签到大屏」** → 会开一个新页面，投影出去即可。
5. 活动不要了，可在「活动管理」列表点 **删除**（会二次确认），或在活动后台点 **删除活动**；
   名册和签到记录会一并删掉、无法恢复。若只是暂时不用，点 **归档** 即可保留数据。

## 第 6 步：用起来

### 会前
1. 后台「导入名册」→ 先「下载模板」→ 在 Excel 里填（**姓名、校区必填**）→ 上传。
2. 检查「应到人数」是否正确。

### 会中
1. 大屏页面右上角可切换 **签到模式 / 签离模式**。
   切换后二维码会立刻换成新的一张、**4 位现场码也会变**，倒计时重新从 20 秒开始计时；
   旧二维码随即失效（防截图转发），请提醒老师用当前屏幕上的码。
2. 参会者扫二维码 → 填姓名、手机号、选校区、**输入大屏上显示的 4 位现场码** → 提交。
3. 大屏右侧「最新动态」实时滚动，已签到/已签离数字每 2 秒刷新。

### 会后
1. 后台 →「导出 Excel」→ 得到四张表：**签到明细 / 应到实到统计 / 缺席名单 / 抽奖记录**。
2. 忘记扫码的老师，用「手动补录」补上（会标记为「补录」）。

## 备选路线：用命令行部署（网页点不动时用这个）

如果 Railway 网页上的 GitHub 授权按钮点不动（一直灰色、点完没反应），用下面这套命令行流程，效果完全一样。

### 最省事：跑一键脚本

项目里已经放好了一个全自动脚本。在 PowerShell 里执行：

```powershell
cd "D:\MiniMax工作站\签到系统"
.\deploy\一键部署.ps1
```

它会自动做完所有事：装 CLI → 登录 → 建项目 → 挂 Postgres → 设环境变量 → 上传部署 →
关联 GitHub 仓库（以后 `git push` 自动重新部署）→ 生成域名并回填 `BASE_URL` → 健康检查。

期间只有**一件事需要你动手**：浏览器弹出后点一次 GitHub 的 **Authorize**。
最后终端会打印网址和 `admin` 密码，请记下来。

> 如果 PowerShell 提示「禁止运行脚本」，先执行一次：
> `Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass`

### 手动分步（想了解每一步时用）

#### A. 装 CLI 并登录

```powershell
npm i -g @railway/cli
railway login
```

- `railway login` 会自动弹出**你自己的 Edge**，在页面里点 GitHub 登录并授权即可；
  - **注意**：登录页的授权窗口只有 **5 分钟**，超时就要重跑一次命令；
  - 如果这台机器连不上 GitHub（国内常见 DNS 污染，表现为网页打不开），就用页面底部的
    **「Log in using email」**，输入邮箱后点邮件里的登录链接，一样能登进去；
- 如果 Edge 没弹出来，改用设备码方式，命令会打印一个网址和验证码：
  ```powershell
  railway login --browserless
  ```
  手动打开它给的网址（形如 `https://railway.com/activate?user_code=XXXX-XXXX`），
  确认设备后回到命令行，提示登录成功即完成。

#### B. 创建项目并挂数据库

```powershell
cd "D:\MiniMax工作站\签到系统"
railway init --name meeting-checkin
railway add --database postgres
railway add --service web
```

> 顺序很重要：**必须先挂 Postgres 再部署**，否则首次构建会因缺 `DATABASE_URL` 失败。

#### C. 设变量并部署

```powershell
railway variables set --service web "DATABASE_URL=`${{Postgres.DATABASE_URL}}" "SECRET_KEY=<随机长字符串>" "ADMIN_PASSWORD=你的密码"
railway up --service web --detach --yes
railway domain --service web --port 8000
```

- `railway variables set` 一次可以设多个变量，中间用空格分隔；
- `railway variables set` 会触发重新部署，**建议先设变量再 `railway up`**，省一次构建；
- `railway up --service web --detach --yes` 上传代码并构建部署；
- `railway domain --service web --port 8000` 生成公网网址，**`--port 8000` 不能省**（否则 502），
  把它填回 `BASE_URL`：
  `railway variables set --service web "BASE_URL=https://你的域名"`

#### D. 关联 GitHub，实现 push 自动部署（可选）

```powershell
railway service list --json
railway service source connect --repo kevin-qingmo/meeting-checkin --branch main --service <服务名>
```

以后每次 `git push`，Railway 会自动重新构建部署。

## 常见问题对照表

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 打开网址显示 502 / Application failed to respond | **域名目标端口不对**（最常见）；或构建失败、服务没起来 | 先在服务卡片 Settings → Networking 把 **Target Port 改成 8000**；命令行等价：`railway domain update 你的域名 --port 8000 --service web`。仍不行则看 Deployments 日志 |
| 日志报 `ModuleNotFoundError: No module named 'psycopg'` | 依赖里缺 psycopg v3 驱动（SQLAlchemy 走 postgres 时默认用它） | `requirements.txt` 必须有 `psycopg[binary]==3.2.3`，改完重新 `railway up` |
| 日志报连不上数据库 | 没设 `DATABASE_URL` | Variables 里加 `DATABASE_URL=${{Postgres.DATABASE_URL}}` |
| 日志报 `SECRET_KEY 仍是默认值，签到码可被伪造，已拒绝启动` | 环境变量没设或拼错 | 到 Variables 加上 `SECRET_KEY`，点 Generate 自动生成，保存后自动重新部署 |
| 扫码后跳转到空白页 | `BASE_URL` 填错 | 改成 `https://你的域名`（不带斜杠），保存后自动重新部署 |
| 大屏二维码一直不变 | 页面没刷新 | 按 `Ctrl+F5` 强制刷新；仍不行则检查 `CYCLE_SECONDS` 是否被改过 |
| 手机提交提示「签到码已刷新」 | 手慢，超过了 40 秒窗口 | 重新扫一次二维码，看最新现场码再填 |
| 手机提交提示「现场码不正确」 | 填的是上一轮的码 | 以大屏当前显示的数字为准 |
| 签到打不开 / 显示未开放 | 时间不在活动时段 | 后台「编辑」检查开始结束时间；注意服务器时区为北京时间 |
| 数据没了 | 用了免费实例且数据库未挂载 | 确认 Postgres 插件存在；免费版建议每月登一次避免休眠 |
| 多人同时签到很慢 | 免费实例性能有限 | Railway 升级付费实例（约 ¥20/月） |

## 安全提醒

- `SECRET_KEY` 决定签到码能否被伪造，**不要提交到 GitHub**（已在 `.gitignore` 中管理环境变量文件）。
- 参会老师手机号属于个人信息，导出表仅在校内使用，不要外传。
- 活动结束后建议把活动「归档」，避免误操作。
