# 设计文档：管理员账号删除 + 活动随机抽签

- 日期：2026-11-17
- 项目：`D:\MiniMax工作站\签到系统`（Flask + PostgreSQL，Railway 部署）
- 配色：日式黑金（墨黑暖调大屏 + 暖米白纸底后台 + 沙金点缀）

## 1. 背景与目标

会议扫码签到系统已上线，现需两项后台管理能力：

1. **管理员账号删除**：创建者（`role=super`）可删除普通管理员账号；被删账号名下的活动一并删除。
2. **活动随机抽签**：在活动后台设置单次抽取人数，从已签到人员中随机抽出对应人数，结果落库留痕，并在签到大屏上滚动展示。

## 2. 已确认的关键决策

| 决策点 | 结论 |
|---|---|
| 删除账号时其活动怎么办 | **一并删除**（级联删除名册、签到、抽奖记录），需二次确认并提示不可恢复 |
| 抽签候选范围 | **只从该活动「已签到」的人中抽取**（扫码与补录均计入） |
| 重复中奖 | 做成**可勾选开关**，默认勾选=排除已中奖者 |
| 中奖名单是否上大屏 | **要**，大屏滚动展示 |
| 抽签记录是否进导出 | **要**，Excel 新增第 4 张表「抽奖记录」 |
| 随机源 | `secrets.SystemRandom()`（系统级密码学随机） |

## 3. 功能一：管理员账号删除

### 3.1 界面
- 账号管理页（`app/templates/admin/users.html`）每行「操作」列新增红色「删除」按钮。
- 当前登录账号（创建者本人）所在行**不显示**删除按钮。
- 点击后弹出确认框，文字需包含该账号名下的活动数量，并说明「名册与签到记录一并删除，且无法恢复」。

### 3.2 后端
新增路由 `POST /admin/users/delete`（`app/routes/admin.py`）：

- 权限：`current_user.is_super` 否则 403（与账号管理页同一守卫）。
- 目标账号 `uid` 不得等于当前登录者 → 403，flash「不能删除当前登录的账号」。
- 级联删除顺序（先子后父，避免外键约束）：
  1. `LotteryRound`（该用户名下活动的中奖轮次）
  2. `CheckIn`（签到记录）
  3. `Roster`（名册）
  4. `Activity`（活动）
  5. `User`（账号本身）
- 完成后 flash「已删除账号 X 及其 N 个活动」，重定向回账号列表。

### 3.3 错误处理
- `uid` 缺失或不是整数 → 400。
- 目标账号不存在 → flash「账号不存在」，不报错 500。

## 4. 功能二：活动随机抽签

### 4.1 数据模型
新增表 `lottery_rounds`（`app/models.py`）：

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | Integer PK | |
| `activity_id` | Integer FK → `activities.id` | 所属活动 |
| `draw_count` | Integer | 本轮**实际抽中**人数（请求人数可能大于可抽人数，落库的是实际抽中数） |
| `winners_json` | Text | 中奖名单 JSON：`[{"name":..., "campus":..., "phone":...}]` |
| `excluded` | Boolean | 本轮是否启用「排除已中奖者」 |
| `operator_id` | Integer FK → `users.id` | 操作人 |
| `created_at` | DateTime | 抽取时间 |

- 活动删除（`activity_delete`）时同步删除该活动的 `LotteryRound`。
- 账号删除时同步删除其名下活动的 `LotteryRound`（见 3.2 顺序）。

### 4.2 去重规则
- 去重键：优先手机号；手机号为空时用「姓名 + 校区」。
- 「已中奖者」= 该活动**所有历史轮次**（无论当时是否勾选排除）里的中奖人。
  即：勾选排除时，后续轮次不会抽中此前任何一轮的中奖人；取消勾选时可重复中奖。

### 4.3 后端

**抽取动作** `POST /admin/activity/<int:activity_id>/lottery`（`app/routes/admin.py`）
- 登录 + 活动归属校验（复用 `get_managed_activity`）。
- 入参：`count`（整数 ≥ 1，默认 1）、`exclude_winners`（勾选框，默认开启）。
- 候选池：该活动的 `CheckIn` 记录（`checked_in_at` 非空即视为已签到；扫码与补录都算）。
- 若勾选排除：剔除历史中奖人。
- 实际抽取人数 `min(count, len(候选池))`；候选池为空 → 返回 `ok=false` 与提示「暂无可抽取人员（需先签到）」。
- 随机：`secrets.SystemRandom().sample(候选池, k)`。
- 写入 `LotteryRound`，返回 JSON：`{ok, message, round:{id, seq, draw_count, winners:[...], created_at, operator}}`。
- 每次抽取**成功**都落一条轮次记录（便于审计）。两种失败都**不落记录**：
  - 候选池为空（无人签到）→ 400「暂无可抽取人员，请先完成签到」；
  - 候选池非空但**全部已中奖**（勾选了「排除已中奖者」且无人可再抽）→ 400
    「候选人员都已中过奖，可开启『允许重复中奖』」，与「暂无可抽取人员」区分开。

**轮次编号口径**：后台历史表格与 Excel 导出统一使用**活动内序号**（该活动内按 id 升序的 1..n），
不使用 `lottery_rounds` 的全局 id（跨活动不连续，复盘时「第几轮」会对不上）。
序号由服务端统一计算（`app/lottery.py` 的 `round_seq_map`），后台与 Excel 取同一来源。

**读取接口** 两个，分工不同：

- `GET /admin/activity/<int:activity_id>/lottery`（`app/routes/admin.py`）——**登录态私有接口**
  - 登录 + 活动归属校验（复用 `get_managed_activity`），他人活动 → 403。
  - 返回该活动**全部**轮次：`{rounds:[{id, seq, draw_count, winners:[...], created_at, operator, excluded}], latest:{...}|null}`。
  - 后台「历史抽奖记录」表格用它（公开接口只给最近 5 轮，第 6 轮以后在后台看不到）。
- `GET /api/activity/<int:activity_id>/lottery`（`app/routes/api.py`）——**公开只读**
  - 供大屏/投屏等匿名场景使用，返回最近 5 轮。
  - 公开响应只保留中奖人姓名与校区，**不含手机号，也不含操作人姓名**；
    操作人等内部信息走上面的登录态私有接口。
  - 注：`/board/<id>`（大屏页面）本身带 `@login_required`，大屏访问者需要登录；
    本公开接口是为「匿名投屏」场景预留的，两者权限层级并不相同。

### 4.4 活动后台界面（`app/templates/admin/dashboard.html`）
- 新增「随机抽签」卡片：
  - 人数输入框（`type=number`，min=1，默认 1）
  - 勾选框「排除已中奖者」（默认勾选）
  - 「开始抽奖」按钮
- 抽奖结果：**深色遮罩弹层**大字展示中奖名单（姓名逐行滚动的视觉效果由 CSS 实现），带「关闭」按钮。
- 卡片下方「历史抽奖记录」表格：轮次 / 抽取时间 / 人数 / 名单 / 操作人 / 是否排除已中奖者。
- 抽奖通过 `fetch('/admin/activity/<id>/lottery', {method:'POST'})` 调用，成功后局部刷新历史表格与遮罩层。

### 4.5 签到大屏（`app/templates/board.html` + `app/static/js/board.js` + `board.css`）
- 右侧新增「中奖名单」卡片（与统计卡、动态列表同一栅格）。
- 每 5 秒轮询 `GET /api/activity/<id>/lottery`；有新轮次时把最新一轮名单置顶并**滚动展示**（CSS 线性循环动画）。
- 无中奖记录时显示「本次暂无抽奖」。
- 配色沿用大屏黑金：卡片底 `rgba(255,255,255,.06)`，边框 `rgba(212,180,140,.14)`，中奖姓名沙金 `#D4B48C`。

### 4.6 Excel 导出（`app/exporter.py`）
- 在现有三张表（签到明细 / 应到实到统计 / 缺席名单）之后**新增第 4 张表「抽奖记录」**：
  列 = 轮次 / 抽取时间 / 抽取人数 / 中奖名单 / 操作人 / 排除已中奖者。
- 「轮次」列用**活动内序号**（与后台历史表格同一口径、同一来源）。
- 表头填充色沿用主色 `8A6B52`。

## 5. 测试方案

### 5.1 pytest（`tests/test_flow.py`，新增约 8 项）
1. 创建者可删除普通管理员账号，账号消失。
2. 删除账号时其名下活动、名册、签到记录、抽奖轮次一并删除。
3. 普通管理员访问 `/admin/users/delete` → 403。
4. 不能删除当前登录账号（403）。
5. 抽签只从已签到的人中抽（未签到者不会被抽中）。
6. 候选不足时按实际人数抽取并如实返回。
7. 勾选「排除已中奖者」时历史中奖人不再被抽中；不勾选时可再次抽中。
8. `GET /api/activity/<id>/lottery` 公开可读且返回最近轮次。
9. 导出 Excel 的 sheetnames 变为 4 张且含「抽奖记录」。
10. 候选池非空但全部已中奖 → 400 且提示「候选人员都已中过奖…」，且**不落轮次记录**。
11. 轮次编号：两个活动各抽一轮，两边的「第 1 轮」一致（活动内序号，不是全局 id）。
12. 后台私有接口 `GET /admin/activity/<id>/lottery` 返回**全部**轮次（抽 6 轮得 6 条），
    未登录 → 302/401/403，他人活动 → 403。
13. 公开只读接口的响应体不含 `operator` 字段与操作人姓名。
14. 活动标题含单引号/换行/`</script>` 时，两个页面的删除确认仍是合法可执行的 JS。
15. 开启 SQLite 外键约束（`PRAGMA foreign_keys=ON`）后：删账号不残留悬空 `operator_id`、
    他人活动仍在且其上轮次 `operator_id` 置空；删带轮次的活动不报错且数据全部清零。
16. 关系集合已被加载时删除活动不得 500（StaleDataError 兜底）。

### 5.2 浏览器端到端（新增 `tools/ui_check_lottery.js`）
- 后台抽奖 → 弹层出现中奖名单 → 历史记录新增一行。
- 大屏页面出现「中奖名单」卡片并滚动展示。
- 取消「排除已中奖者」后同一轮可再次抽中同一人。
